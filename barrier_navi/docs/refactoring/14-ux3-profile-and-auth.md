# UX-3: プロフィール・認証操作の明確化

## 目的

UX-3では、プロフィールでお気に入り駅を登録する操作と、ログイン画面でアカウントを作成する操作を、キーボード利用時にも完結できるようにした。既存のプロフィールJSON、認証API、セッション方式は変更していない。

| 対象 | 改善内容 | 維持した契約 |
| --- | --- | --- |
| お気に入り駅検索 | 駅名候補をコンボボックス／リストボックスとして操作可能にする | `/stations/search` の検索形式 |
| お気に入りの編集 | 追加・削除後に保存が必要であることを状態通知する | `favorite_stations` は駅ID配列 |
| プロフィール保存 | 成功メッセージを画面上に残し、自動遷移をしない | `preferred_features`、`favorite_stations`、`disability_type` のJSON |
| 新規登録 | モーダルを意味論的なダイアログとし、Esc・Tab・復帰フォーカスを扱う | `/auth/signup` |
| パスワードリセット | 未提供の送信フォームとAPI呼び出しを削除する | 既存のログイン・登録・ゲスト導線 |

## お気に入り駅検索

駅名入力欄には `role="combobox"`、候補領域には `role="listbox"`、個別候補には `role="option"` を付与した。入力欄にフォーカスを置いたまま上下矢印で候補を移動し、Enterで追加できる。現在の候補は `aria-activedescendant` と `aria-selected` で表し、視覚上も選択状態を区別する。

候補件数、検索失敗、候補なしの状態は検索用の控えめな状態通知へ送る。追加・削除後はお気に入り用の別の状態通知で「保存すると反映されます」と伝えるため、検索結果の通知と編集状態の通知が混ざらない。

## プロフィール保存

保存成功後の自動ホーム遷移を廃止した。保存結果を `role="status"` の要素へ表示してフォーカスを移し、利用者が「保存された」ことを確認してから次の画面へ移動できるようにした。

> 保存完了の通知は「プロフィールを保存しました。変更は次回の駅検索に反映されます。」とし、保存済みの優先設備・お気に入り駅が一覧検索に影響することを明示する。

## 新規登録ダイアログ

新規登録モーダルには `role="dialog"`、`aria-modal="true"`、見出しとの関連付けを追加した。開く直前の操作要素を保存し、閉じるとその要素へフォーカスを戻す。ダイアログ表示中はEscで閉じ、Tab／Shift+Tabはダイアログ内で循環する。

登録成功時のブラウザ標準ダイアログは廃止し、ログインフォームにユーザー名を転記したうえで、画面内の状態メッセージで次の操作を案内する。

## 未提供機能の整合性

パスワードリセットはサーバー側の提供契約に含まれていないため、リンクに見える案内、入力フォーム、送信ボタン、`/auth/reset-password` を呼び出すクライアントコードを削除した。代わりに、利用できないことと問い合わせ先が必要であることを非操作的な注記として表示する。

## 回帰条件と検証

| 項目 | 確認内容 |
| --- | --- |
| コンボボックス | `aria-expanded`、`aria-controls`、`aria-activedescendant`、`listbox`／`option` の関係を維持する |
| キーボード操作 | 上下矢印、Enter、Escapeで候補選択・追加・閉じる操作が行える |
| 保存確認 | 保存成功メッセージが自動遷移前に消えず、フォーカス可能である |
| ダイアログ | ダイアログの意味論、Esc、フォーカストラップ、復帰フォーカスを維持する |
| 未提供機能 | リセット送信UIと `/auth/reset-password` のクライアント参照がない |
| 契約互換性 | プロフィールJSONと認証APIのURL・形式は変更しない |

静的アクセシビリティ回帰は `backend/tests/test_accessibility_markup.py` に追加し、TypeScriptビルド、フロントエンド単体テスト、バックエンド全テスト、ローカルHTTP応答を確認する。
