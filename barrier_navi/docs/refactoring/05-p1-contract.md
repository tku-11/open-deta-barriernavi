# P1 契約仕様: スコア・フィルタ・プロフィール更新

**決定日:** 2026-08-21  
**目的:** スコア計算、一覧絞り込み、プロフィール保存について、実装・API・画面・テストが従う唯一の仕様を定める。

## 1. スコア仕様

スコアはカテゴリごとに定義された評価項目の **達成数を単純集計**する。重み付け、部分点、利用者ごとの基準値は P1 の対象外であり、API は `weights` を受け付けない。各項目は達成時に 1 点、未達成時に 0 点とする。

| カテゴリ | 総項目数 | 内訳 |
| --- | ---: | --- |
| 身体 | 12 | フラグ 5、割合 3、数値 4 |
| 聴覚 | 4 | フラグ 4 |
| 視覚 | 10 | フラグ 6、割合 1、数値 3 |

評価の詳細は以下のとおりとする。

| 型 | 達成条件 | 欠損・不正値 | 詳細表示 |
| --- | --- | --- | --- |
| `flag` | DB値が文字列として `"1"` と一致する | 未達成 | `○` または `×` |
| `number` | 数値が `required` 以上 | 0 として未達成 | 実数値 |
| `ratio` | `denominator > 0` かつ `numerator / denominator >= required` | 未達成 | `分子/分母 (割合%)` |

`percentage` は `(met_items / total_items) × 100` を小数第 1 位で丸めた値とする。カテゴリ間では総項目数が異なるため、スコア値を利用可否の断定やカテゴリ横断のランキングに使わない。

## 2. 一覧フィルタ仕様

`GET /api/{body|hearing|vision}/stations` の `filters` は JSON 配列とする。各フィルタは **当該評価項目を達成した駅だけを残す**。複数条件は AND とする。

| 型 | フィルタ条件 |
| --- | --- |
| `flag` | 値が `1` |
| `number` | 値が `required` 以上 |
| `ratio` | 分母が 0 より大きく、割合が `required` 以上 |

これにより、一覧で「条件を満たす」と、詳細スコアで「達成」とが同じ意味になる。未知のフィルタキーや不正な JSON は無視し、SQL 条件には追加しない。`weights` は未対応であり、API 仕様に記載しない。

## 3. プロフィール更新仕様

プロフィール更新の正規メソッドは `PATCH /api/auth/profile` とする。後方互換のため `PUT` も同じ部分更新として受け付ける。認証済みセッションの本人だけを更新対象とし、リクエスト中の `user_id` は受け付けない。

| フィールド | 省略 | 有効値 | 空配列 | `null`・不正型 |
| --- | --- | --- | --- | --- |
| `username` | 現在値を保持 | 1文字以上の文字列 | 該当なし | 400 |
| `disability_type` | 現在値を保持 | 配列 | 値をクリア | 400 |
| `favorite_stations` | 現在値を保持 | 整数または整数文字列の配列 | 値をクリア | 400 |
| `preferred_features` | 現在値を保持 | 配列 | 値をクリア | 400 |

少なくとも一つの更新可能フィールドを送る必要がある。新規プロフィール行を作成する場合、送られなかった選好フィールドは空（DB上は `NULL`）として保存する。

## 4. API 契約の不変条件

一覧 API は `success`、`data`、`count`、`total_count` を返す。各一覧要素には `station_id`、`station_name`、`score` を含め、`score` は `met_items`、`total_items`、`percentage`、`label` を持つ。詳細 API は上記に加え、総項目数と同数の `metrics` を返す。

P1 の自動テストでは、評価閾値、分母 0、全達成、カテゴリ別総項目数、絞り込み条件、一覧・詳細レスポンス、プロフィールの省略保持と明示クリアを固定する。
