# UX-4: 駅詳細の意思決定支援

## 目的

UX-4では、駅詳細画面で総合ラベルだけを見るのではなく、達成項目数、未達項目、保存済みの優先設備に対応する評価項目をまとめて確認できるようにした。スコアの計算方法、駅詳細API、プロフィールJSONは変更していない。

| 対象 | 改善内容 | 維持した契約 |
| --- | --- | --- |
| 詳細要約 | スコア、達成数、未達数を文章とリストで示す | カテゴリ別スコア定義 |
| 未達項目 | 最大3項目を要約し、表の判定にも補足語を加える | `metrics[].met` |
| 優先設備 | 保存済み優先設備を既存の対応表でメトリクスへ対応付ける | `/auth/profile` と `preferred_features` |
| モバイル表 | 列見出しを各セルのラベルとして再提示する | 駅詳細レスポンス |

## 詳細要約

詳細画面に「この駅を選ぶための要約」を追加した。ここでは評価ラベルに加え、達成項目数、全項目数、達成率、未達項目数を文章と箇条書きで表示する。未達項目がある場合は、最初の3項目を名前で示すため、利用者は全表を読む前に確認すべき点を把握できる。

> 未達の表記は、色だけではなく「未達（基準を満たしていない）」というテキストでも示す。達成側も同様に「達成（基準を満たす）」と表示する。

これは新たな評価や推奨を追加するものではなく、既存の `metrics[].met` とスコア集計を再整理して表示するものである。

## 保存済み優先設備との照合

ログイン済みでプロフィールに優先設備を保存している場合、詳細画面は既存の `metricKeysForPreferredFeature` を利用して、現在のカテゴリに対応する評価項目を特定する。そのうえで「優先設備に対応する評価項目のうち何項目を達成しているか」と、該当する未達項目を要約に追加する。

プロフィール取得に失敗した場合やログインしていない場合でも、駅詳細の表示は中断しない。優先設備の補足だけを省略し、通常のスコア・未達項目の比較は利用できるようにした。

## モバイルでの評価表

幅640px以下では、横スクロール中心の表を評価項目ごとのカード状表示へ切り替える。各データセルは `data-label` から列名を再表示するため、見出し行を視覚的に隠した後も「項目」「設置の有無と数」「基準値」「判定」の意味を失わない。

デスクトップでは従来の表形式を維持する。表のキャプションと判定列はUX-1からの構造を保ち、UX-4は比較の文脈とモバイル可読性を補強する。

## 回帰条件と検証

| 項目 | 確認内容 |
| --- | --- |
| 詳細要約 | `decision-summary`、要約文、要約リストが存在する |
| 優先設備照合 | 既存の `metricKeysForPreferredFeature` のみを使用し、API契約を変更しない |
| 非色覚的表現 | 達成／未達にテキスト上の意味を含める |
| モバイル表示 | 各表セルに `data-label` を持ち、狭い画面でラベルを再表示する |
| エラー耐性 | プロフィール読込の失敗が駅詳細表示を妨げない |
| 配布成果物 | `frontend/dist/detail.js` をTypeScriptビルドで同期する |

静的アクセシビリティ回帰は `backend/tests/test_accessibility_markup.py` に追加し、TypeScriptビルド、フロントエンド単体テスト、バックエンド全テスト、詳細ページ・詳細API・配布モジュールのローカルHTTP応答を確認する。
