# UX-1 アクセシビリティ基盤と状態通知

**決定日:** 2026-08-22  
**目的:** 既存のAPI、スコア、認証、ページング契約を変更せず、駅検索・比較・詳細確認をキーボード、支援技術、狭い画面でも理解・操作しやすくする。

## 1. 対象と非対象

UX-1は、共通配色、フォーカス可視化、動的状態通知、一覧・詳細のHTMLセマンティクス、ユーザー向け見出しを対象とする。プロフィールのコンボボックス化、ログインモーダルのフォーカストラップ、詳細のモバイルカード代替は後続のUX-3およびUX-4で扱う。

| 対象 | 実施内容 | 契約への影響 |
| --- | --- | --- |
| 配色 | 補助文、主操作、成功・エラー、フォーカス、キーワードチップの可読性を改善。 | なし |
| フォーカス | `:focus-visible`、縮小モーション設定、画面非表示テキストを共通化。 | なし |
| 駅一覧 | 結果範囲・読込・空・エラーの状態通知、セマンティックなページ移動、リンク型駅カード。 | URLとJSONは不変 |
| 駅詳細 | 表の`caption`、判定列、読込・エラーの状態通知。 | URLとJSONは不変 |
| 回帰 | 静的アクセシビリティテストを追加。 | なし |

## 2. 配色とフォーカス

標準文字と背景の主要組み合わせを再計算し、本文14.33:1、補助文5.41:1、白文字と主操作色6.75:1、成功文5.93:1、エラー文6.79:1、フォーカス枠5.02:1、キーワードチップ7.55:1を確認した。通常文字の4.5:1を下回っていた従来の補助文、主操作、成功文、キーワードチップは置き換えた。[1]

すべての操作部品に`:focus-visible`でオフセット付きのフォーカス枠を適用する。キーボードで操作できる要素の現在位置を視認可能にすることは、WCAG 2.2のFocus Visibleの目的に沿う。[2]

## 3. 状態通知

一覧ページには`role="status"`の結果状態領域を追加し、読込中、総件数と表示範囲、該当なし、取得失敗を通知する。プロフィールの読込・保存、ログインの成功・エラー、詳細の読込・エラーにも適切な`status`または`alert`を付与した。

動的に追加され、フォーカスを移さない読込・結果・成功・エラーの情報を支援技術が取得できるようにすることは、WCAG 2.2のStatus Messagesの趣旨と整合する。[3]

## 4. セマンティックな操作

駅カードはクリック処理を持つ`div`から、カテゴリと駅IDを保持した詳細URLへの`<a>`に変更した。これにより、マウス、キーボード、リンク一覧、支援技術で同じ詳細遷移を利用できる。スコア進捗は`role="progressbar"`と値を持ち、詳細表には色だけに依存しない「達成／未達」列を設けた。
